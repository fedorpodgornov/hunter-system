# СИСТЕМА — трекер тренировок с прокачкой уровня

Дневник тренировок в стиле интерфейса
«Системы» из аниме. Реальная тренировка даёт опыт, опыт поднимает уровень,
уровень открывает ранги E → EX, ежедневные квесты и характеристики.

## Файлы

- `index.html` — разметка, подключает `styles.css` и четыре скрипта
- `styles.css` — оформление (тёмная тема, свечение, «системные» панели)
- `data.js` — константы (типы тренировок, виды добавок, ранги, квесты, достижения, лимиты честности), состояние, localStorage
- `engine.js` — расчёты: опыт, уровень, ранги, характеристики, серии дней, генератор квестов, правила честности, расписание напоминаний
- `ui.js` — отрисовка панелей, диаграммы характеристик, графика за 7 дней, журналов добавок и нарушений
- `app.js` — обработка событий, экспорт/импорт JSON, напоминания и файл .ics, сброс, запуск
- `config.js` — адрес проекта Supabase и публичный anon-ключ (пусто = офлайн-режим)
- `sync.js` — клиент Supabase без библиотек: вход, выгрузка журнала, подкачка, друзья, лидеры
- `social.js` — панель «Сеть»: аккаунт, друзья, таблица лидеров, нарушения и баны
- `supabase/schema.sql` — таблицы, RLS и серверные функции: опыт считает только база
- `actions.json` — сценарий браузерной проверки (имя, тренировка, добавка, нарушение правил, сброс, ошибки ввода)
- `screenshots/panel-1440.png`, `screenshots/panel-390.png` — вид панели с демо-данными

## Сборка и проверка

Готовый офлайн-файл лежит в корне чата: `..\..\hunter-system.html` (всё в одном файле,
CSS и JS встроены, интернет не нужен).

```
multitool-node --skill websites site.cjs bundle sites/hunter-system/index.html hunter-system.html
multitool-node --skill websites site.cjs check hunter-system.html
multitool-node --skill websites verify.cjs hunter-system.html --actions sites/hunter-system/actions.json
```

После правок в исходниках повторить `bundle`, затем `check`.
Сценарий проверки `actions.json` рассчитан на чистое хранилище: если браузер уже
хранит прогресс, прогонять его нужно на копии с `localStorage.clear()` при загрузке.

## Формулы

- опыт за тренировку: `минуты × 1,6 × интенсивность × тип` + 15 за первую тренировку дня
- порог уровня: `90 × уровень^1,15`; уровень считается из суммарного опыта
- ранги: E (1–9), D (10–19), C (20–29), B (30–44), A (45–59), S (60–79), EX (80+)
- характеристики: 10 базово + бонус класса + вклад тренировок и квестов + 1 за уровень
- бонус за все три ежедневных квеста: +120 опыта и день в серию
- добавки: отдельный журнал приёмов (что, доза, время, за 7 дней), опыта и
  характеристик не даёт и влияет только на историю наблюдений
- напоминания: три точки расписания (тренировка, добавки, итог дня). Внутри
  открытой страницы — карточка Системы и системное уведомление браузера;
  для напоминаний при закрытой странице выгружается `.ics` с ежедневными
  событиями, его добавляют в календарь телефона
- честность: одна запись до 240 минут, до 360 минут и до 6 записей в день.
  Записи вне правил сохраняются в журнале без опыта и характеристик,
  три такие записи замораживают начисление опыта на 24 часа

## Границы офлайн-версии

Всё работает в одном файле и в браузере, сервера нет. Поэтому друзья, общая
таблица лидеров, синхронизация между устройствами и настоящие баны требуют
аккаунтов и бэкенда: без них любой сможет подменить свои данные, а общих
данных просто негде хранить. Правила честности здесь — самопроверка, а не
защита от других людей.

## Подключение сервера Supabase

1. Создать проект на supabase.com (бесплатного тарифа хватает).
2. В SQL Editor выполнить целиком `supabase/schema.sql`.
3. В Settings → API скопировать Project URL и `anon public` ключ в `config.js`.
4. Пересобрать: `site.cjs bundle`, затем проверить `check`.
5. Выложить файл на хостинг с https (подойдёт GitHub Pages) — с `file://`
   запросы к серверу запрещены браузером.

Что это даёт: аккаунты по почте, синхронизация журнала кнопками «Выгрузить»
и «Подтянуть», заявки в друзья по нику, таблица лидеров среди себя и друзей,
серверный учёт нарушений.

Как устроена защита: опыт, уровень и заморозку считает только база (функция
`log_workout`), клиент не имеет права писать в таблицы — на них отозваны
`insert/update/delete`, а профиль меняется только через `set_profile`
(ник и класс). Поэтому подделать опыт в таблице лидеров нельзя, а бан и
заморозку нельзя снять себе: их снимает владелец проекта в панели Supabase.

Автоматика: 3 нарушения за 24 часа → заморозка начисления на 24 часа,
10 нарушений за 7 дней → автобан. Нарушения видны в панели «Сеть».

Важно про ключи и данные: `anon`-ключ публичный и безопасен только вместе
с RLS из `schema.sql`; ключ `service_role` в клиент вставлять нельзя никогда.
Серверы Supabase находятся не в России, поэтому при публичном запуске с
данными российских пользователей нужно учитывать требования 152-ФЗ о
локализации персональных данных — для демонстрации достаточно почты и ника,
лишние данные собирать не нужно.

## Состояние проекта Supabase

Подключено и проверено на живом проекте:

- проект `hunter`, ref `dhllkljjdantrovchuym`, регион `eu-west-2`, статус ACTIVE_HEALTHY;
- схема применена скриптом `supabase/provision.ps1` (Management API + персональный токен);
- URL и `anon`-ключ записаны в `config.js` и вшиты в собранные артефакты;
- в проекте включено автоподтверждение почты (`mailer_autoconfirm = true`):
  SMTP у проекта не настроен, письма упирались бы в лимиты, а регистрация
  в приложении сразу даёт сессию. Выключается в Authentication → Sign In / Providers.

Скрипты (нужен персональный токен Supabase, не пароль):

```
# организации и проекты, только чтение
powershell -File sites/hunter-system/supabase/provision.ps1 -Token sbp_...

# схема + запись config.js
powershell -File sites/hunter-system/supabase/provision.ps1 -Token sbp_... -RunSchema -WriteConfig

# проверка сети на живом проекте (создаёт и удаляет тестовых пользователей)
powershell -File sites/hunter-system/supabase/smoke-test.ps1 -Token sbp_...
powershell -File sites/hunter-system/supabase/smoke-test.ps1 -Token sbp_... -CheatOnly
powershell -File sites/hunter-system/supabase/smoke-test.ps1 -Token sbp_... -CleanupOnly
```

Проверено на живом проекте: регистрация и вход по паролю, `set_profile`,
начисление опыта за честную запись, отказ в опыте за запись длиннее 240 минут,
запись нарушения, кириллица в текстах базы, заявка в друзья, принятие заявки,
таблица лидеров с отметкой «это ты», и главное — прямые запросы в таблицы
`workouts` и `profiles` отклоняются базой, подделать опыт нельзя.
Тестовые пользователи после проверки удалены (в базе их ноль).
